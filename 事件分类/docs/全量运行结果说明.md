## ⚠️ 关于WARNING日志的说明

### 日志示例

```
WARNING:src.qwen_classifier:预测分类 '占道经营' 不在事件类型 '城市管理' 的有效分类中
WARNING:src.qwen_classifier:预测分类 '租赁纠纷' 不在事件类型 '矛盾纠纷' 的有效分类中
```

### 为什么会出现这些警告？

#### 原因1: 模型使用了不同的表述方式

**训练数据中的标准名称**:
- `占用、堵塞、封闭消防通道、消防登高场地` (完整的官方名称)

**模型预测的名称**:
- `占道经营` (简化表述)
- `占道、堵塞、封闭消防通道` (部分内容)
- `占道经营-流动摊贩` (更具体的描述)

#### 原因2: 分类名称不在映射表中

查看训练数据发现，**"城市管理"类型**确实没有"占道经营"这个二级分类：

**城市管理的31个标准分类**:
1. 街面秩序
2. 市容环境
3. 占用、堵塞、封闭消防通道、消防登高场地 ← 这是标准名称
4. 宣传广告
5. ... 等等

但模型可能理解事件是关于"占道经营"，所以输出了这个语义相近的分类。

## 🔍 问题分析

### 主要的WARNING类型

1. **占道经营相关** (~60次)
   - 模型预测: `占道经营`、`占道经营-流动摊贩`、`占道设摊`
   - 标准分类: 应该是`街面秩序`或其他
   
2. **消防通道相关** (~40次)
   - 模型预测: `占道、堵塞、封闭消防通道`
   - 标准分类: `占用、堵塞、封闭消防通道、消防登高场地`
   - 差异: "占道"vs"占用"，缺少"、消防登高场地"

3. **租赁纠纷相关** (~10次)
   - 模型预测: `租赁纠纷`
   - 标准分类: 应该是`债务纠纷`或`经济纠纷`
   - 问题: 矛盾纠纷类型下没有"租赁纠纷"这个分类

## 💡 这些WARNING是好事还是坏事？

### ✅ 好的方面

1. **系统正常工作**: 限制功能正确阻止了不合理的分类
2. **保护数据质量**: 避免了错误的分类被采纳
3. **提供反馈**: 警告日志帮助我们发现模型的"想法"

### ⚠️ 需要改进的方面

1. **模糊匹配太严格**: 
   - `占道` vs `占用` 应该被识别为相近
   - `占道、堵塞、封闭消防通道` vs `占用、堵塞、封闭消防通道、消防登高场地`

2. **分类名称不统一**:
   - 训练数据中可能有"占道经营"的事件，但被标注为"街面秩序"
   - 需要检查标注一致性

3. **提示词可能需要优化**:
   - 强调必须使用列表中的**完整标准名称**
   - 不要简化或改写

```python
def classify_single(event):
    """
    完整的预测逻辑
    """
    # 1. 提取信息
    event_type = event['事件类型']  # 例如: "城市管理"
    description = event['事件描述']
    
    # 2. 获取有效分类 (新增功能✨)
    valid_categories = get_categories_for_type(event_type)
    # 城市管理 → [街面秩序, 市容环境, 占用、堵塞、封闭消防通道、消防登高场地, ...]
    
    # 3. 构建提示词
    prompt = f"""
    当前事件类型: {event_type}
    
    可选的二级分类: {', '.join(valid_categories)}
    
    事件描述: {description}
    
    请仅输出分类名称
    """
    
    # 4. 调用API
    result = call_qwen_api(prompt)  # 例如返回: "占道经营"
    
    # 5. 验证结果
    if result in valid_categories:
        return result, 0.9  # ✅ 精确匹配
    else:
        # 尝试模糊匹配
        match = fuzzy_match(result, valid_categories)
        if match:
            return match, 0.7  # ✅ 模糊匹配
        else:
            logger.warning(f"预测分类 '{result}' 不在有效分类中")
            return None, 0.0  # ❌ 匹配失败 → FAILED
```
