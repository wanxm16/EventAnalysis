但是，**有512个事件的描述中明确包含"占道经营"字样**，这些事件被标注为**"街面秩序"**（95.3%）。

## 💡 为什么会这样？

### 原因1: 标注体系的设计

**分类层级**:
```
一级分类(事件类型): 城市管理
  ├─ 二级分类: 街面秩序 ← 这是标准分类名
  │   └─ 包含的内容:
  │       • 占道经营
  │       • 流动摊贩
  │       • 违规停车
  │       • 其他影响街面秩序的行为
  │
  ├─ 二级分类: 市容环境
  │   └─ 包含: 垃圾、绿化、卫生等
  │
  └─ 其他二级分类...
```

**设计逻辑**:
- **"街面秩序"** = 抽象的分类名（更高层次）
- **"占道经营"** = 具体的事件类型（更底层的描述）

标注体系选择用**抽象的分类名**，而不是**具体的事件描述**。

### 原因2: 标注的一致性原则

**标注员的思考过程**:

```
看到事件: "流动摊贩占道经营，影响交通"

思考: 
  Q: 这是什么问题？
  A: 影响了街面的秩序和通行
  
  Q: 应该归到哪个二级分类？
  A: "街面秩序" (标准分类名)
     
  不选择: "占道经营" (虽然描述用了这个词，但这不是分类名)
```

**标注原则**:
- 使用预定义的标准分类名
- 不使用事件描述中的具体词汇作为分类名
- 保持分类体系的一致性

### 原因3: 分类粒度的选择

**如果把"占道经营"作为独立分类**:

可能的细分:
```
街面秩序
  ├─ 占道经营
  │   ├─ 流动摊贩
  │   ├─ 店铺外摆
  │   ├─ 跨门经营
  │   └─ ...
  ├─ 违规停车
  │   ├─ 机动车违停
  │   ├─ 非机动车乱停
  │   └─ ...
  └─ ...
```

**问题**: 分类会变得非常多（可能200+个），过于细化

**选择**: 用"街面秩序"这个更抽象的名称，涵盖所有影响街面秩序的行为

## 🔍 深层原因分析

### 1. 训练数据的特点

**训练数据中的"标注"**:
```
事件描述                    → 二级分类
─────────────────────────────────────────
"流动摊贩占道经营..."       → 街面秩序
"无证摊贩占道设摊..."       → 街面秩序
"商铺跨门经营占道..."       → 街面秩序
"路边有垃圾..."           → 市容环境
"绿化带损坏..."           → 园林绿化
```

**特点**: 
- 标注用的是**预定义的分类名称**
- 不直接使用事件描述中的词汇

### 2. Few-shot学习的局限

**Few-shot示例**:
```python
示例1：
  事件描述：流动摊贩占道经营需要处理
  二级分类：街面秩序  ← 标注

示例2：
  事件描述：无证摊贩占道设摊影响交通
  二级分类：街面秩序  ← 标注
```

**模型学习到的**:
```
从示例中学习:
  "占道经营" → 应该分类为 "街面秩序"
  
但模型的理解:
  "占道经营" 本身就是一个很好的分类名啊！
  为什么不直接用"占道经营"？
```

**结果**: 模型"创造性"地使用了"占道经营"这个更直观的名称

### 3. 提示词的影响

**当前提示词**:
```
可选的二级分类包括：
街面秩序、市容环境、宣传广告...

事件描述：流动摊贩占道经营

请输出该事件的二级分类名称
```

**模型的两种理解**:

理解A（正确）:
```
我看到列表中有"街面秩序"
事件描述是占道经营
我应该输出 → "街面秩序" ✅
```

理解B（创造性）:
```
事件描述中有"占道经营"
这是个很精确的分类啊
我输出 → "占道经营" ❌
（虽然语义对，但不在列表中）
```

## 💡 这揭示了什么问题

### 1. 分类名称的抽象程度问题

**现状**: 分类名称都很抽象
```
• 街面秩序 (抽象) ← 包含占道经营、违停等
• 市容环境 (抽象) ← 包含垃圾、卫生等
• 消防安全隐患 (抽象) ← 包含各种具体隐患
```

**模型的自然倾向**: 使用更具体、更直观的名称
```
• 占道经营 (具体) ← 更直观
• 垃圾处理 (具体) ← 更清晰
• 电瓶车充电 (具体) ← 更明确
```

### 2. Few-shot学习的挑战

**挑战**: 从少量示例中学习抽象规则

```
给模型3个示例:
  1. "占道经营" → 街面秩序
  2. "流动摊贩" → 街面秩序
  3. "违规停车" → 街面秩序

模型需要学会:
  这些具体问题都归类为"街面秩序"这个抽象概念
  
难点:
  • 只有3个示例，学习不充分
  • "街面秩序"这个词很抽象
  • 模型可能更倾向用具体词汇
```

### 3. 标注一致性vs自然语言理解

**标注员视角** (人工标注):
```
任务: 将事件归类到预定义的145个分类中
方法: 严格遵循分类定义
结果: 占道经营 → 街面秩序 ✅（符合规范）
```

**模型视角** (AI理解):
```
任务: 理解事件语义，给出最合适的分类
方法: 自然语言理解
结果: 占道经营 → 占道经营 ✅（更直观）
```

**矛盾**: 
- 标注遵循**规范性**
- 模型追求**直观性**

## 🔧 这就是为什么需要别名映射表

### 别名表的作用：桥接两种逻辑

```
┌──────────────────┐         ┌──────────────────┐
│   模型的逻辑      │         │   标注的逻辑      │
│                  │         │                  │
│  "占道经营"      │         │  "街面秩序"      │
│  (具体、直观)    │         │  (抽象、规范)    │
└──────────────────┘         └──────────────────┘
         │                           ▲
         │      🔑 别名映射表          │
         └───────────────────────────┘
         
别名表: "占道经营" → "街面秩序"
作用: 翻译模型语言为标注语言
```

### 解决的矛盾

```
矛盾:
  模型说: "这是占道经营"
  标注说: "这应该归类为街面秩序"
  
问题:
  两者说的是同一件事
  但用的名称不同
  
解决:
  别名表建立对应关系
  "占道经营"(模型语) = "街面秩序"(标注语)
  
效果:
  模型继续说"占道经营"
  系统自动理解为"街面秩序" ✅
```

训练数据:
