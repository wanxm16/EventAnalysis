# 基于事件类型的分类限制功能说明

## 📋 功能概述

系统现已支持**基于事件类型限定二级分类范围**的功能。在预测二级分类时，系统会先根据事件的一级分类（事件类型）来限制可能的二级分类选项，而不是在所有145个二级分类中进行预测。

## 🎯 修改目的

### 之前的问题
- 预测时不考虑事件类型，在全部145个二级分类中选择
- 可能预测出与事件类型不匹配的二级分类
- 预测范围过大，降低准确率

### 修改后的改进
- ✅ 根据事件类型自动限定二级分类范围
- ✅ 提高预测准确性和合理性
- ✅ 减少不合理的分类预测
- ✅ 提升模型效率

## 📊 映射关系统计

系统从训练数据中提取了**29种事件类型**到**145个二级分类**的映射关系：

| 事件类型 | 二级分类数量 | 示例二级分类 |
|---------|------------|------------|
| 矛盾纠纷 | 28个 | 债务纠纷、劳动人事纠纷、邻里纠纷、物业管理纠纷等 |
| 城市管理 | 31个 | 街面秩序、市容环境、宣传广告、公用设施等 |
| 消防安全 | 24个 | 灭火器材问题、电动车违规充电、出租房设施安全等 |
| 交通安全 | 10个 | 机动车路面违停、道路安全问题、交通附属设施等 |
| 治安隐患 | 14个 | 防溺水、违法犯罪线索、其他治安隐患等 |
| 生态环境 | 9个 | 水体污染、空气污染、固体废物污染等 |
| 食药安全 | 8个 | 食品安全宣传、食品卫生问题、操作人员健康证等 |
| ... | ... | ... |

完整映射关系保存在 `data/event_type_category_mapping.json`

## 🔧 技术实现

### 1. 数据映射文件生成
```python
# 从训练数据中提取事件类型到二级分类的映射关系
# 保存为 data/event_type_category_mapping.json
```

### 2. 分类器初始化时加载映射
```python
# 在QwenClassifier.__init__()中
self.event_type_mapping = self._load_event_type_mapping()
```

### 3. 预测时限定分类范围
```python
# 根据事件类型获取有效的二级分类列表
valid_categories = self._get_valid_categories_for_event_type(event_type)

# 在这个范围内进行预测
prompt = f"""当前事件类型：{event_type}
该事件类型下可选的二级分类包括：{valid_categories}"""
```

### 4. 结果验证
```python
# 验证预测结果是否在有效分类范围内
if predicted_category in valid_categories:
    confidence = 0.9
else:
    # 尝试模糊匹配（仅在有效范围内）
    best_match = self._fuzzy_match(predicted_category, valid_categories)
```

## 📝 使用示例

### 示例1：矛盾纠纷类事件

```python
test_event = {
    '事件描述': '居民反映小区业主房子涉嫌违建，希望社区处理',
    '事件类型': '矛盾纠纷',
    '区县名称': '海曙区',
    '镇街名称': '高桥镇'
}

# 系统会在"矛盾纠纷"类型下的28个二级分类中选择
# 可能的分类：物业管理纠纷、其他纠纷、邻里纠纷等
```

### 示例2：城市管理类事件

```python
test_event = {
```

## ✨ 核心优势

1. **提高准确率**：缩小预测范围，减少错误分类
2. **增强合理性**：确保预测结果与事件类型匹配
3. **提升效率**：减少模型需要考虑的选项数量
4. **更好的提示词**：给模型提供更明确的上下文信息

## 🔍 注意事项

1. 如果事件没有提供事件类型，系统会使用所有145个分类
2. 如果事件类型在映射中不存在，系统会警告并使用所有分类
3. 映射关系基于训练数据构建，确保了准确性
4. 模糊匹配也限制在有效分类范围内进行
