# 分类别名映射表用途详解

## 🎯 核心用途（一句话）

**自动将模型输出的非标准分类名称转换为训练数据中的标准分类名称，避免预测失败。**

---

## 📋 具体说明

### 什么是别名映射表？

**文件位置**: `data/category_aliases.json`

**内容示例**:
```json
{
  "占道经营": "街面秩序",
  "租赁纠纷": "债务纠纷",
  "占道、堵塞、封闭消防通道": "占用、堵塞、封闭消防通道、消防登高场地"
}
```

**含义**: 
- 左边（key）: 模型可能输出的**非标准名称**
- 右边（value）: 训练数据中的**标准分类名称**

---

## 🔍 为什么需要它？

### 问题场景

#### 场景1: 模型输出了简化的名称

```
事件描述: "流动摊贩占道经营，影响交通"
事件类型: 城市管理
真实分类: 街面秩序

模型理解: ✅ 这是占道经营问题（理解正确）
模型输出: "占道经营"
问题: ❌ 训练数据中没有"占道经营"这个分类名
      ✅ 但有"街面秩序"分类（这类事件被标注为街面秩序）
```

**没有别名表时**:
```
系统检查: "占道经营" 在31个城市管理分类中吗？
结果: ❌ 不在
模糊匹配: ❌ 失败
最终: FAILED + WARNING日志
```

**有别名表时**:
```
系统检查: "占道经营" 在31个城市管理分类中吗？
结果: ❌ 不在
别名映射: ✅ "占道经营" → "街面秩序"
再次检查: "街面秩序" 在分类中吗？
结果: ✅ 在！
最终: 街面秩序（成功）✅
```

#### 场景2: 模型输出了不完整的名称

```
事件: "楼道电瓶车堵住消防通道"
真实分类: "占用、堵塞、封闭消防通道、消防登高场地"（很长的名称）

模型输出: "占道、堵塞、封闭消防通道"
问题: 
  1. "占道" vs "占用" (字不同)
  2. 缺少 "、消防登高场地" (不完整)
```

**有别名表**:
```json
{
  "占道、堵塞、封闭消防通道": "占用、堵塞、封闭消防通道、消防登高场地"
}
```

**效果**:
```
模型输出: "占道、堵塞、封闭消防通道"
别名映射: ✅ 转换为完整标准名称
结果: "占用、堵塞、封闭消防通道、消防登高场地" ✅
```

#### 场景3: 模型输出了语义相近但名称不同的分类

```
事件: "租房押金不退，与房东纠纷"
真实分类: 债务纠纷

模型理解: ✅ 这是租赁相关的纠纷（理解正确）
模型输出: "租赁纠纷"
问题: ❌ 矛盾纠纷类型下没有"租赁纠纷"这个分类
      ✅ 但有"债务纠纷"（押金纠纷属于债务问题）
```

**别名表**:
```json
{
  "租赁纠纷": "债务纠纷"
}
```

**效果**:
```
模型输出: "租赁纠纷"  
别名映射: ✅ 映射到"债务纠纷"
结果: 债务纠纷 ✅
```

## 💻 代码实现

### 在分类器中的使用

```python
# src/qwen_classifier.py

class QwenClassifier:
    def __init__(self):
        # ...
        # 加载别名映射表
        self.category_aliases = self._load_category_aliases()
        # 输出: {'占道经营': '街面秩序', '租赁纠纷': '债务纠纷', ...}
    
    def _load_category_aliases(self):
        """加载分类别名映射"""
        with open('data/category_aliases.json', 'r') as f:
            return json.load(f)
    
    def _fuzzy_match(self, predicted_category, valid_categories):
        """增强的模糊匹配"""
        
        # 🔑 优先级最高：别名映射
        if predicted_category in self.category_aliases:
            alias_target = self.category_aliases[predicted_category]
            if alias_target in valid_categories:
                logger.debug(f"别名匹配: '{predicted_category}' → '{alias_target}'")
                return alias_target  # 返回标准名称
        
        # 如果别名映射失败，继续其他匹配策略...
        # Layer 2: 完全匹配
        # Layer 3: 包含匹配
        # Layer 4: 关键词匹配
        # Layer 5: 相似度匹配
```

## 💡 设计哲学

### 为什么不用复杂算法？

**对比**:

| 方法 | 优点 | 缺点 |
|------|------|------|
| **别名映射表** | 简单、快速、准确、可控 | 需要人工维护 |
| 机器学习相似度 | 自动化 | 可能误匹配、不可控 |
| 规则引擎 | 灵活 | 复杂、难维护 |

**选择别名表的原因**:
1. ✅ **准确性**: 人工定义，不会错
2. ✅ **简单性**: 字典查找，代码简单
3. ✅ **可维护**: JSON文件，易于编辑
4. ✅ **可追溯**: 每个映射都有明确依据
5. ✅ **性能好**: O(1)查找，极快

### 设计原则

1. **优先级最高** - 最先检查，快速返回
2. **人工定义** - 保证准确性
3. **易于扩展** - 随时添加新映射
4. **独立于代码** - 修改映射无需改代码
