# 手工创建事件簇功能文档

## 1. 功能概述

手工创建事件簇功能允许用户在聚合事件列表页面手动选择多个相关事件，创建自定义的事件簇。该功能补充了系统自动聚类的不足，让用户能够根据业务需求和专业判断将相关事件进行归类管理。

## 2. 功能入口

- **页面位置**：聚合事件列表页面 (`/cluster-list`)
- **操作入口**：页面右上角的"创建事件簇"按钮

## 3. 核心功能

### 3.1 事件搜索与筛选
- 支持按事件编号、事件描述进行模糊搜索
- 实时搜索，输入关键词即可动态过滤事件列表
- 显示事件的基本信息：编号、描述、镇街、级别、上报时间

### 3.2 事件选择机制
- 采用穿梭框（Transfer）组件进行事件选择
- 左侧显示可选事件列表，右侧显示已选事件
- 支持批量选择和单个选择
- 支持在已选事件中进行二次搜索和筛选

### 3.3 冲突检测
- **冲突定义**：事件已存在于其他事件簇中
- **检测机制**：实时检测所选事件是否与现有簇存在冲突
- **冲突处理**：
  - 冲突事件会标红显示
  - 创建时自动过滤冲突事件
  - 提供冲突详情（显示事件所属的簇ID）

### 3.4 簇信息配置
- **簇描述**：必填项，用于描述该事件簇的共同特征
- **字符限制**：描述最多200个字符
- **标识信息**：手动创建的簇会自动标记为"手动"类型

## 4. 操作流程

### 4.1 创建流程
1. 点击"创建事件簇"按钮
2. 在搜索框中输入关键词筛选事件（可选）
3. 从左侧事件列表中选择相关事件
4. 填写事件簇描述
5. 确认创建，系统会：
   - 过滤冲突事件
   - 创建新的事件簇
   - 跳转到簇详情页面

### 4.2 冲突处理流程
1. 系统检测到冲突事件时显示警告
2. 用户可选择：
   - 移除冲突事件继续创建
   - 取消操作重新选择
3. 确认创建时系统自动过滤冲突事件

### 5.4 API接口

#### 获取事件列表
```
GET /api/events
参数：
- page: 页码
- page_size: 每页数量
- search: 搜索关键词
```

#### 检查事件冲突
```
POST /api/events/check-clusters
请求体：{
  "event_ids": ["事件ID1", "事件ID2", ...]
}
响应：{
  "conflicts": [
    {
      "event_id": "事件ID",
      "cluster_id": "簇ID",
      "cluster_description": "簇描述"
    }
  ]
}
```

#### 创建事件簇
```
POST /api/clusters/manual
请求体：{
  "description": "簇描述",
  "event_ids": ["事件ID1", "事件ID2", ...],
  "created_by": "创建者",
  "cluster_type": "manual"
}
响应：{
  "cluster_id": "新簇ID",
  "message": "创建成功"
}
```

## 7. 用户体验设计

### 7.1 界面特性
- **直观的穿梭框设计**：清晰区分可选和已选事件
- **实时搜索反馈**：输入即搜，提升操作效率
- **冲突可视化**：红色标签明确标识冲突事件
- **操作状态提示**：loading状态和成功/失败提示

### 7.2 交互优化
- **搜索防抖**：避免频繁API调用
- **自动过滤**：智能处理冲突事件
- **表单验证**：确保必填项完整
- **一键清空**：支持快速重置选择

## 8. 错误处理

### 8.1 常见错误场景
- **网络异常**：API调用失败时使用模拟数据
- **数据为空**：无可选事件时显示提示信息
- **全部冲突**：所选事件都存在冲突时阻止创建
- **表单验证**：描述未填写时显示错误提示

### 8.2 降级策略
- API不可用时自动切换到模拟数据模式
- 保持功能的基本可用性
- 友好的错误提示和引导

## 9. 性能优化

### 9.1 数据加载
- **分页加载**：限制每次加载事件数量（100条）
- **按需搜索**：根据搜索关键词动态加载
- **缓存机制**：避免重复加载相同数据

### 9.2 渲染优化
- **虚拟滚动**：大数据量时保持流畅性能
- **防抖搜索**：减少不必要的搜索请求
