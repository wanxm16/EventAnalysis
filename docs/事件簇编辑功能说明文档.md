# 事件簇编辑功能说明文档

## 1. 功能概述

事件簇编辑功能允许用户在事件簇详情页面对事件簇进行动态管理，包括从簇中删除事件和向簇中添加事件。该功能提供了灵活的事件聚类管理能力，支持手动调整系统自动生成的聚类结果。

## 2. 功能入口

- **页面位置**：事件簇详情页面 (`/clusters/{eventUID}`)
- **操作入口**：
  - 点击"编辑Cluster"按钮进入编辑模式
  - 编辑模式下的"添加事件"按钮
  - 每个事件条目的删除按钮

## 3. 核心功能

### 3.1 编辑模式切换
- **进入编辑模式**：点击"编辑Cluster"按钮
- **退出编辑模式**：再次点击"退出编辑"按钮
- **编辑状态指示**：页面标题显示"编辑模式"标签

### 3.2 删除事件功能
- **删除位置**：每个事件时间线条目的删除按钮
- **删除逻辑**：从当前事件簇中移除指定事件
- **确认机制**：删除前显示确认对话框
- **自动处理**：删除后事件将创建新的独立簇

### 3.3 添加事件功能
- **添加入口**：编辑模式下的"添加事件"按钮
- **事件选择**：通过事件ID输入要添加的事件
- **目标簇选择**：可选择将事件添加到当前簇或其他簇
- **冲突检测**：自动检测事件是否已属于其他簇

### 3.4 操作历史与撤销
- **操作记录**：记录所有编辑操作的历史
- **撤销功能**：支持撤销最近的操作
- **操作类型**：区分添加和删除操作

## 4. 操作流程

### 4.1 删除事件流程
1. 进入事件簇详情页面
2. 点击"编辑Cluster"按钮进入编辑模式
3. 在需要删除的事件条目上点击删除按钮
4. 确认删除操作
5. 系统执行删除并创建新的独立事件簇
6. 页面自动刷新显示最新结果

### 4.2 添加事件流程
1. 在编辑模式下点击"添加事件"按钮
2. 在弹窗中输入要添加的事件ID
3. 选择目标事件簇（默认为当前簇）
4. 点击确定执行添加操作
5. 如果事件已属于其他簇，系统显示确认对话框
6. 确认后执行事件移动操作

### 4.3 撤销操作流程
1. 在编辑模式下查看操作历史
2. 点击"撤销上次操作"按钮
3. 系统恢复到操作前的状态
4. 更新页面显示和操作历史

### 5.3 核心函数
- `removeEventFromCluster()` - 从簇中删除事件
- `addEventToCluster()` - 向簇中添加事件

### 5.4 API接口

#### 删除事件
```
POST /api/clusters/{clusterUID}/edit
请求体：{
  "operation": "remove_event",
  "event_id": "事件ID",
  "operator": "操作者"
}
响应：{
  "success": true,
  "message": "操作成功消息"
}
```

#### 添加事件
```
POST /api/clusters/{clusterUID}/edit
请求体：{
  "operation": "add_event",
  "event_id": "事件ID",
  "operator": "操作者",
  "target_cluster": "目标簇ID"
}
响应：{
  "success": true,
  "message": "操作成功消息"
}
```

#### 获取事件簇信息
```
GET /api/events/{eventId}/cluster
响应：{
  "cluster_id": "簇ID",
  "cluster_description": "簇描述",
  "cluster_url": "簇详情链接"
}
```

#### 撤销操作
```
POST /api/clusters/undo/{operationId}
请求体：{
  "operator": "操作者"
}
响应：{
  "success": true,
  "message": "撤销成功"
}
```

#### 获取操作历史
```
GET /api/clusters/{clusterUID}/operations
响应：{
  "operations": [
    {
      "id": "操作ID",
      "type": "操作类型",
      "eventId": "事件ID",
      "timestamp": "操作时间",
      "description": "操作描述"
    }
  ]
}
```

## 7. 业务逻辑

### 7.1 事件删除逻辑
1. **权限检查**：确认用户有删除权限
2. **依赖检查**：检查删除对簇的影响
3. **执行删除**：从当前簇中移除事件
4. **创建新簇**：为删除的事件创建独立簇
5. **更新统计**：重新计算簇的统计信息

### 7.2 事件添加逻辑
1. **事件验证**：验证事件ID的有效性
2. **冲突检测**：检查事件当前归属状态
3. **用户确认**：如有冲突则请求用户确认
4. **执行移动**：将事件从原簇移动到目标簇
5. **更新关联**：更新相关簇的信息

### 7.3 撤销操作逻辑
1. **操作查找**：根据操作ID查找操作记录
2. **状态检查**：确认操作可以被撤销
3. **逆向操作**：执行与原操作相反的操作
4. **记录更新**：更新操作历史状态

## 8. 错误处理

### 8.1 常见错误场景
- **事件不存在**：输入的事件ID不存在
- **权限不足**：用户没有编辑权限
- **网络异常**：API调用失败
- **数据冲突**：并发操作导致的数据不一致

### 8.2 错误处理策略
- **友好提示**：显示具体的错误信息和解决建议
- **操作回滚**：失败时自动回滚到操作前状态
- **重试机制**：网络错误时提供重试选项
- **数据同步**：定期刷新页面数据保持一致性
