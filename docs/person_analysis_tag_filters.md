# 人员分析标签筛选功能产品说明文档

## 1. 背景与目标
- **背景**：人员分析页面目前按姓名 / 手机号 / 身份证等基础字段检索，对人员标签（如重点关注、重点职业、特殊身份）无法快速筛选。随着人员画像能力增强，运营同学希望一键筛出具备某类标签的人群，提升研判效率。
- **目标**：在人员分析列表新增人口标签筛选能力，支持组合筛选、快速查看标签命中情况，并为后续的导出/订阅做准备。
- **价值**：
  - 运营可快速定位重点人群，减少手动 Excel 对比。
  - 支持多标签交叉查询，利于事件溯源和预警。
  - 提供清晰的标签展示，提升人员画像的使用率。

## 2. 适用用户
| 角色 | 诉求 |
| --- | --- |
| 运营专员 | 筛出“重点关注 + 高风险”人员，进行电话回访 |
| 分析师 | 利用标签组合快速验证模型命中情况 |
| 主管领导 | 查看重点人群规模变化、关注重点标签分布 |

## 3. 主要功能范围
1. **标签列表展示**：在筛选区域展示可用的标签分类与标签值，支持多选。
2. **标签筛选逻辑**：标签之间 AND 关系，同一分类内多选为 OR 关系（可配置）。
3. **标签命中提示**：列表内人员展示命中的标签，并可查看全部标签。
4. **筛选状态提示**：页面顶部显示当前筛选标签，可一键清除。
5. **导出影响**：导出结果将带上筛选条件及标签列。

## 4. 详细需求说明
### 4.1 标签数据结构
- 标签分类示例：
  - **风险级别**：重点关注、涉稳重点、特殊关注
  - **职业属性**：出租车司机、网约车司机、医护人员等
  - **警务联动**：警综命中、人口库命中
- 后端返回格式：
  ```json
  {
    "categories": [
      {
        "id": "risk",
        "name": "风险级别",
        "type": "multi_or", // multi_or | multi_and
        "tags": [
          { "id": "risk_focus", "label": "重点关注", "count": 256 },
          { "id": "risk_high", "label": "高风险", "count": 87 }
        ]
      },
      {
        "id": "occupation",
        "name": "职业属性",
        "type": "multi_or",
        "tags": [ ... ]
      }
    ]
  }
  ```
- 人员数据结构新增字段：`tags: [{ id, label, category_id }]`。

### 4.2 筛选交互
- 筛选区域：
  - 分类以折叠面板展示，默认展开“风险级别”。
  - 标签以 Checkbox Button 展示，支持多选，显示数量（可选）。
  - 支持关键字搜索标签。
- 选择规则：
  - 同一分类内多选 → OR 关系（可后续配置），多分类组合 → AND。
  - 允许最多 10 个标签同时选中，超过阈值提示。
- 提示区域：
  - 页面顶部显示已选标签 chips，如“风险级别：重点关注、高风险”。
  - 提供“一键清除”按钮。

### 4.3 列表展示
- 在人员列表中的“标签”列显示命中标签，最多显示 3 个，超出时提供“更多”弹窗。
- 鼠标 hover 显示完整标签清单。
- 支持按标签排序（可选，按标签数降序）。

### 4.4 导出与订阅
- 导出文件包含“标签”列，默认导出所有命中标签（逗号分隔）。
- 导出文件头部写入筛选条件（含标签）。
- 若订阅功能上线，标签条件需要写入订阅配置。

## 5. 接口设计
| 接口 | 方法 | 描述 |
| --- | --- | --- |
| `/api/person-tags/options` | GET | 获取标签分类及标签选项 |
| `/api/person-analysis` | GET | 增加 `tags=risk_focus,risk_high` 参数，用于筛选 |
| `/api/person-analysis/export` | GET | 导出结果，沿用现有导出逻辑，增加标签列 |

### 5.1 `/api/person-analysis` 参数扩展
- `tags`：标签 ID 列表（逗号分隔）。
- `tag_logic`：保留扩展字段，默认为 `AND`（不同分类之间）。
- 响应数据增加 `tags` 字段。

### 5.2 数据筛选逻辑
1. 将 `tags` 拆分为分类维度。
2. 每个分类按 OR 关系合并条件。
3. 分类之间取交集（AND 关系）。
4. 查询支持索引或使用缓存加速。

## 6. UI 原型概述
- 筛选区域左侧增加“人口标签”模块。
- 标签显示为 Pill 样式按钮（选中高亮）。
- 列表列示例：
  | 姓名 | 手机号 | 标签 |
  | --- | --- | --- |
  | 张三 | 138****1111 | `重点关注` `警综命中` ... |
  - 点击“更多”展示底部抽屉，显示全部标签和来源。

## 7. 性能与安全
- 标签数据缓存 5 分钟，避免频繁请求。
- 防止恶意组合导致查询过慢：限制标签组合数，必要时提示分开筛选。
- 导出时权限校验，与人员分析页面一致（仅授权用户可导出）。

## 8. 验收标准
- 可以根据任意标签组合筛出正确数据。
- 列表中标签展示完整且可查看详情。
- 导出结果包含标签列且与列表一致。
- 当选择超出限制时有明确提示，清除筛选后数据恢复。

## 9. 风险及缓解
| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| 标签数据缺失 | 筛选命中不准确 | 初始化时与标签服务对齐，提供兜底提示 |
| 查询性能下降 | 页面加载慢 | 对标签字段增加索引，必要时分页查询 |
| 标签分类过多 | 交互复杂 | 支持折叠/搜索，设置常用标签优先展示 |
