# 月度报告自动生成产品需求文档

## 1. 背景与目标
- **背景**：目前运营同事需要在 Word 模板中手动替换数据与图表，耗时且易出错。随着事件数据规模与领导对月报的依赖度提升，亟需建设可配置、可自动生成的月度报告能力。
- **目标**：提供模板化、自动化的月报生成流程，确保每月按时产出上一月的标准报告草稿，并支持人工校对、发布、导出。
- **价值**：
  - 节省运营团队 60% 以上重复劳动。
  - 提高指标数据的准确性与时效性（当日生成 T-1 月报）。
  - 为领导层提供稳定、统一格式的汇报材料。

## 2. 用户与场景
| 角色 | 使用场景 | 关注点 |
| --- | --- | --- |
| 运营专员 | 查看生成的月报草稿，编辑润色并发布 | 草稿生成准时、数据准确、编辑体验好 |
| 数据分析师 | 维护模板与指标占位符、调整图表展示 | 模板易于配置、占位符可校验 |
| 主管领导 | 每月例会前快速浏览报告并导出 Word | 内容可靠、排版统一、导出便捷 |

## 3. 范围定义
- **主要功能**
  1. **模板管理**：模板 CRUD、Markdown/DSL 编辑、预览、占位符校验。
  2. **报告计划配置**：指定月份、生成周期（每月/手动）、生成日、模板选择。
  3. **自动生成草稿**：按计划生成上一月草稿，填充指标与图表。
  4. **编辑与发布**：富文本编辑、指标预览、发布固化、导出 Word。
  5. **导入/导出**：模板导入导出（Markdown），报告导出 Word。
- **不包含**
  - 审批流、消息通知（后续规划）。
  - 多语言、移动端适配。
  - 自动邮件推送。

## 4. 功能需求
### 4.1 模板管理
- 模板字段：`id`, `name`, `description`, `default_title_format`, `content_md`, `created_at`, `updated_at`。
- 支持 Markdown + 占位符 DSL（`[KPI:指标名|period=@month|scope=全区]`, `[CHART:图表名称|code=...]`）。
- 功能点：
  - 列表查看、搜索、创建、编辑、删除（引用模板不可删）。
  - 保存时对占位符语法进行校验，提示非法类型/缺少参数。
  - 模板预览：调用现有 Markdown 渲染器显示效果。
  - 模板导入/导出：支持 `.md` 文件。

### 4.2 报告计划配置
- 新建报告弹窗字段：
  | 字段 | 说明 |
  | --- | --- |
  | 月份 | 目标月份（例如 2025-09 表示生成 8 月月报） |
  | 生成周期 | `monthly` / `manual` |
  | 生成日 | 1-31，仅当周期为 `monthly` 时展示 |
  | 模板 | 下拉选择模板 |
  | 标题 | 默认由模板 `default_title_format` + T-1 月生成 |
  | 初始内容 | 模板 `content_md` 渲染后的 Markdown |
- 自动填充逻辑：
  1. 选择月份或模板时，若用户未手动修改，自动更新标题与正文。
  2. T-1 计算：`monthLabel = {目标月份 -1 月}`，如 2025-09 → “8月份”。
- 列表展示新增列：生成配置（每月 X 日 / 手动）、模板名称。

### 4.3 自动生成草稿
- 定时任务：每日 00:30 执行。
- 流程：
  1. 查询 `schedule_type='monthly'` 的配置。
  2. 若当前日期匹配 `schedule_day`，则计算目标月份（当前月份）。
  3. 检查目标月份是否已有草稿/发布报告，若无则创建。
  4. 生成标题、正文，状态设为 `draft`，记录 `template_id/name`。
  5. 写入日志（operation_logs）。

### 4.4 编辑、预览、发布
- 延续现有编辑器能力（占位符渲染、指标预览、图表预览）。
- 发布时固化取值并写入 `report_snapshot_values.json`。
- 导出 Word 走现有接口。
- 支持手动触发“立即生成”接口方便运营补救。

### 4.5 模板占位符与数据
- 支持占位符类型：`KPI`, `KPI_MOM_PCT`, `KPI_MOM_DIR`, `CHART`, `click`。
- 生成报告时参数替换规则：
  - `period=@month` → 目标月份（T-1）。
  - 图表渲染调用 `/api/charts/render`。
- 若指标缺失，渲染为 `—` 并标记在预览列表。

### 5.2 templates.json
参见模板字段定义，存储在 `data/templates.json`。

## 6. API 设计
| 接口 | 方法 | 描述 |
| --- | --- | --- |
| `/api/report-templates` | GET | 模板列表、支持 `keyword` 搜索 |
| `/api/report-templates` | POST | 新建模板 |
| `/api/report-templates/{id}` | PUT | 更新模板 |
| `/api/report-templates/{id}` | DELETE | 删除模板（需确认未被引用） |
| `/api/reports` | POST | 创建报告（增加 `schedule_*`、`template_*` 字段） |
| `/api/reports/schedule/run` | POST | 手动触发当日生成（运营后台） |
| `/api/reports/{id}/preview` | POST | 预览（现有接口继续使用） |
| `/api/reports/{id}/publish` | POST | 发布（现有接口） |
| `/api/reports/{id}/export` | GET | 导出 Word（现有接口） |

## 7. 界面与交互要点
1. **报告列表页**
   - 新增“生成配置”“模板”列。
   - “新建报告”弹窗增加生成周期、生成日、模板选择，自动生成标题与正文，手动修改后不再被覆盖。
2. **模板管理页**（新增）
   - 左侧列表 + 右侧编辑器结构；支持 Markdown 编辑、预览、占位符提示。
3. **ReportEdit 页**
   - 保持现有功能，新增模板信息展示。

## 8. 运维与日志
- 每次定时任务执行写入 `operation_logs.json`：任务状态、生成报告 ID、耗时、错误信息。
- 模板操作（新增/修改/删除）记录在操作日志中，便于追溯。

## 9. 成功指标（KPIs）
| 指标 | 目标 |
| --- | --- |
| 自动生成成功率 | ≥ 99% | 
| 运营手动调整耗时 | 对比旧流程减少 60% |
| 报告发布时间 | 在生成日当天 12:00 前完成 |

## 10. 里程碑 & 资源
| 里程碑 | 时间 | 内容 |
| --- | --- | --- |
| M1 | T+3 天 | 模板管理页面 & API |
| M2 | T+7 天 | 报告创建弹窗改造，模板数据联动 |
| M3 | T+10 天 | 定时任务 & 日志 | 
| M4 | T+14 天 | 全量联调，QA 验收 | 

- **资源需求**：前端 1 人、后端 1 人、QA 0.5 人。

## 11. 风险与应对
| 风险 | 影响 | 缓解措施 |
| --- | --- | --- |
| 定时任务重复执行 | 生成重复草稿 | 增加幂等校验，记录已生成月份 |
| 模板占位符错误 | 报告生成失败 | 模板保存时强制校验 + 生成失败通知 |
| 旧数据缺失字段 | 列表展示异常 | 数据迁移补齐 `schedule_type=manual` |
| 指标数据缺值 | 报告关键数字为空 | 预览列表提示缺失项，提供手动编辑 |
